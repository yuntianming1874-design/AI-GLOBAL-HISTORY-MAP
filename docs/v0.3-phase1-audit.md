## 2. 当前 HistoryContext（src/lib/explorer.ts）

```ts
interface HistoryContext {
  year: number | null;          // ?year     钳制 500–1000
  startYear: number | null;     // ?start    显式聚焦区间（含端点）
  endYear: number | null;       // ?end
  eventId: string | null;       // ?event    事件高亮/定位
  personId: string | null;      // ?person   人物一生聚焦 + 图谱
  civilizationId: string | null;// ?civ      文明过滤
  locationId: string | null;    // ?loc      地图 flyTo + 打开详情
}
```

- URL 白名单：`year/start/end/civ/event/person/loc` + `lang`（EXTRA_ALLOWED_PARAMS）。
- **Provider 有未知参数清洗器**（`hasUnknownParams` → `sanitizeContextParams`）：
  任何不在白名单的 URL 参数会被一次性剥离 —— **V0.3 若新增 `journey`/`step` 参数必须
  先扩展白名单，否则会被洗掉**（关键改造点）。
- `dispatchHistoryAction`（`dispatch`）是唯一导航入口，8 种动作：
  `OPEN_EVENT`（跳 /events/[id]）、`OPEN_PERSON`（跳 /people?person=）、
  `OPEN_LOCATION`（patch loc）、`SET_YEAR`（跳 /?year=）、
  `FOCUS_CIVILIZATION`（patch civ）、`FOCUS_TIMELINE`（跳 / 带 year/start/end/event/person）、
  `FOCUS_MAP`（跳 /map?loc&event&year）、`FOCUS_PERSON_GRAPH`（跳 /people?person=）。
- `HistoryEntityRef{id, type: event|person|civilization|location|territory}` 与
  `HistoryEntityLink{ref + label}` 已存在 —— V0.3 `NarrationContext.surroundingEntities`
  可直接复用此类型。

## 3. 当前页面导航流程

```
用户动作                     URL 变化                             组件响应
─────────                    ─────────                            ─────────
Home 点 Timeline CTA    →    #timeline 锚点                       Timeline 滚动
点地图/人物/AI CTA       →    /map、/people、/chat                 整页切换
Timeline dot 点击        →    dispatch OPEN_EVENT → /events/e-751-talas   Event Detail 页
Map marker 点击          →    EventModal / LocationModal（页内浮层）
People 图节点点击         →    /people?person=p-xuanzong → PersonDrawer（页内抽屉）
AI 回答里的实体 chip      →    EntityLinks → dispatch（见上 8 种动作）
AI 回答里的建议按钮       →    ActionButtons → dispatch
```

要点：
- 跨页导航走 `router.push`（进浏览器历史），页内聚焦走 `patch`（URL 参数写回）。
- Event Detail / People / Map / Chat 之间**没有页面内互嵌**——每次切换都是整页跳转；
  V0.3 JourneyExplorer 的"Timeline + Map + Story + People/Events/AI"同屏布局需要新的
  页面内组合（复用组件而非复用页面壳）。
- `/events/[id]` 的 "open map / open people / view timeline / ask AI" 按钮全部是显式
  URL 链接（`/?event=&year=`、`/map?event=&year=`、`/people?event=`、`/chat?event=`），
  与 dispatch 语义一致，可照此模式做 Journey 的跨组件动作。

## 4. 当前实体引用机制

1. **AI → 实体**：LocalAssistant 的 `linkFor(entry)` / `actionsFor(entry)` 从知识库
   （即 seed）生成 `HistoryEntityLink[]` / `HistoryNavigationAction[]`；
   OpenAIAssistant 的 JSON 输出经 `KNOWN_IDS` + `LINK_TYPES` **白名单校验**，
   编造的 entityId 会被丢弃（§40"AI 不得生成不存在 entityId"已在 V0.2.2 满足）。
   ⚠️ 但 OpenAIAssistant 的 actions 过滤**只放行 5 种**（OPEN_EVENT / OPEN_PERSON /
   OPEN_LOCATION / FOCUS_CIVILIZATION / SET_YEAR）——FOCUS_TIMELINE / FOCUS_MAP /
   FOCUS_PERSON_GRAPH 被过滤；V0.3 若 AI 需要推荐"View on timeline/map"，此白名单必须扩展。
2. **组件 → 实体**：chatBlocks 的 `EntityLinks` 按 `link.type` 分发 dispatch
   （event/person/location/civilization 已覆盖，territory 空操作）；
   `ActionButtons` 渲染全部 action 类型并 dispatch —— **V0.3 新增 START_JOURNEY
   action 时只需在此两处加分支 + explorer.ts 类型 + Provider dispatch 实现**。
3. **检索**：`searchHistoryEntities` 4 级有序（精确名/别名嵌入/名称包含/全文评分），
   别名表 67 条（含"怛罗斯之战"→ e-751-talas）—— Journey step 的 entityId 解析
   与 AI 上下文实体匹配都走它，无需新机制。
4. **链接**：`linkFor` 只对种子实体生成链接；`personLink/eventLink/locationLink`
   同样受 seed 约束。字符串猜 id 在代码中不存在。

## 附：审计中发现的风险点（无阻断）

1. **URL 清洗器**会剥离未知参数 —— journey/step 必须先入白名单（最高优先级）。
2. **OpenAIAssistant actions 白名单不全**（缺 3 种 FOCUS_*）——Navigator 推荐受限。
3. **Gao Xianzhi 不在 seed**（e-751-talas participants 为空）——Journey 1 需规避或人工补数。
4. HomeView 目前无 Journey 入口；导航（header/footer）未发现统一 nav 组件
   （各页只有 PageHeader），/journeys 入口需加到 HomeView 与 PageHeader。
5. ComparisonPanel 按世纪分桶，与"751 年世界同期"按年需求不同——新建而非复用。
6. `OPEN_EVENT`/`OPEN_PERSON`/`FOCUS_MAP`/`FOCUS_TIMELINE` 会**整页跳转**；
   JourneyExplorer 内需要页内版本（Journey 内 step 用 patch 而不是跳页），
   需新增 `FOCUS_EVENT`（页内 patch eventId，不跳 /events/[id]）一类动作，
   或在 JourneyExplorer 内直接用 selectEvent/selectPerson patch API。
